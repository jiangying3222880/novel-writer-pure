### 2.2 各项目最值得借鉴的设计

| 设计 | 具体内容 | 对你的价值 |

## 三、优化方案（按优先级排序）

### P0 — 立即可做，风险低，价值高

#### 3.1 潜文本卡简化交互
**现状**：13个专业字段，用户门槛高
**方案**：
```
新增"意图输入"流程：
1. 用户用自然语言描述本章意图（1-2句话）
2. AI解析意图，生成结构化确认（3-5个要点）
3. 用户确认/补充
4. AI自动填充13字段（对用户透明）
5. 高级用户仍可手动微调13字段
```
**改动范围**：subtext.py + subtext_tab.py + writing_engine.py
**预计工作量**：2-3天

#### 3.2 反AI味升级为"三遍法"+误杀防护
**现状**：6维平级检测，可能误杀好表达
**方案**：
- 借鉴awesome-novel-skill的三遍法：Pass1去泛化→Pass2去书面化→Pass3回自然感
- 加入误杀防护：角色化表达/对话特例/功能豁免不改
- 保留你现有的6维作为底层检测，三遍法作为上层编辑
**改动范围**：anti_ai.py
**预计工作量**：2-3天

#### 3.3 题材特化写法指导
**现状**：genre_presets只有数据（名称/关键词），缺写法指导
**方案**：
- 为每个题材（至少仙侠/都市/玄幻/悬疑/言情5大类）添加：
  - 该题材的AI常见病句正反例
  - 该题材的写法要点（节奏/对话/场景偏好）
  - 该题材的禁忌（不能写的套路）
- 存储为knowledge库的一部分，写作时按题材加载
**改动范围**：genre_presets.py + knowledge/ + writing_engine.py
**预计工作量**：3-5天

### P1 — 需要验证后做，价值高

#### 3.4 世界图谱UI验证与优化
**现状**：后端完整，UI展示效果未验证
**方案**：
1. 先跑一个测试项目（哪怕是mock数据），验证图谱导出格式
2. 参考inkos的PlayHud（仪表盘式展示）和51mazi的关系图谱
3. 优化图谱可视化：节点按实体类型着色，边按共现频次粗细
4. 加入时间轴视图：拖动时间轴看实体出场/消失变化
**改动范围**：entity_tab.py + 可能需要新增图谱渲染组件
**预计工作量**：3-5天

#### 3.5 长篇节奏验证方案
**现状**：Orchestrator+压力计未跑长篇
**方案**：
1. 用mock数据模拟100章的写作流程
2. 验证：压力计zone变化是否合理？改稿循环是否有效？追读率调整是否触发？
3. 加入"节奏报告"：每10章输出一次节奏分析（压力分布/钩子密度/情绪曲线）
4. 参考inkos的32维审计，补充叙事层面的节奏检查
**改动范围**：orchestrator.py + pressure.py + 新增节奏报告
**预计工作量**：3-5天（验证）+ 2-3天（优化）

#### 3.6 风格进化端到端验证
**现状**：style_learner+style_variant未端到端测试
**方案**：
1. 模拟测试：生成3版正文→模拟用户选择→看风格指纹是否收敛
2. 验证spread衰减是否合理（4→2→1）
3. 验证style_learner的5维计算是否准确（对比人工判断）
4. 加入"风格漂移检测"：如果用户选择偏离已学风格，提醒确认
**改动范围**：style_learner.py + style_variant.py
**预计工作量**：2-3天

### P2 — 中期规划，价值高但成本也高

#### 3.7 记忆系统动态进化
**现状**：L1-L4是静态分层
**方案**：
- 借鉴awesome-novel-skill的use_count机制
- 每条记忆记录使用次数，高频使用的自动从L3升到L2
- 长期未用的记忆自动降级到L4
- 加入"记忆压缩"：50+条时保留最近30+摘要
**改动范围**：memory.py + memory_manager.py
**预计工作量**：3-5天

#### 3.8 伏笔生命周期管理
**现状**：伏笔在L1中是静态的
**方案**：
- 借鉴inkos的伏笔管理：每个伏笔有状态(埋设/推进/回收/过期)
- 加入半衰期：伏笔超过N章未回收→告警
- 加入依赖关系：伏笔A的回收依赖伏笔B
- 自动检测：写新章时检查是否有伏笔该回收了
**改动范围**：memory.py + world_observer.py
**预计工作量**：3-5天

#### 3.9 独立评审环节（Reader Agent）
**现状**：6维评估偏理性，缺感性读者视角
**方案**：
- 新增reader agent：沉浸阅读→口语化反馈
- 三问：读完什么感受？会不会追读？哪里最爽/最无聊？
- 与现有critic agent互补：critic评结构，reader评体验
**改动范围**：agents/新增reader.py + orchestrator.py
**预计工作量**：2-3天

## 四、借鉴策略总结

### 4.1 你的项目 vs 竞品的独特优势（保持）

1. **潜文本卡13字段+6问** — 行业唯一，简化交互后更强
2. **压力计4zone** — 行业唯一，验证后是护城河
3. **声音档案5维** — 行业唯一
4. **风格指纹+学习+变体** — 行业唯一，验证后是护城河
5. **世界图谱5模块联动** — 行业最完整
6. **7步编排** — 独创流程
7. **工程质量** — 69套测试，行业最强
8. **插件+VSCode+Agent** — 可扩展性最强

### 4.2 应该借鉴的设计（按优先级）

| 优先级 | 借鉴内容 | 来源 | 符合"疏导"哲学？ |
|--------|---------|------|-----------------|
| P0 | 反AI味三遍法+误杀防护 | awesome-novel-skill | ✅ 教导式，不是禁止 |
| P0 | 题材特化正反例 | awesome-novel-skill | ✅ 教AI该怎么做 |
| P0 | 动态记忆晋升降级 | awesome-novel-skill | ✅ 自进化，不需用户干预 |
| P1 | 独立reader评审 | awesome-novel-skill | ✅ 读者视角反馈 |
| P1 | 伏笔生命周期 | inkos | ✅ 自动追踪，不需用户管 |
| P1 | 叙事层状态快照 | inkos | ✅ 与世界观层互补 |
