# 单元驱动编排重构计划 v3（最终版）

## 概述

**目标**：用 1 个月时间让 Story Engine 真正跑起来，单元驱动为唯一模式，章节降级为 Render。

**核心哲学**：**LLM 不是核心，Story Engine 才是核心。** LLM 是执行器，可替换；Story Engine 是护城河。

**目录策略**：**不改名、不重组目录、不删模块**——目录是组织问题，不影响架构。第一层核心做完，目录结构自然清晰。

## 1 个月路线图（5 件事）

### 工作 1：Virtual Unit 适配层（2 天）

**目的**：消灭双轨架构，让 Story Engine 永远只看到 Unit 接口。

**改动**：
- 新增 [virtual_unit_adapter.py](file:///d:/novel-writer-pure-v3.4/app/services/virtual_unit_adapter.py)
  - `wrap_chapter_as_virtual_unit(chapter_id) -> str` — 老 Chapter 自动包装成 Unit
  - `VirtualUnit` 类实现 `story_unit_service_v2` 的 `get/update/list` 接口
  - 底层操作实际 chapter 数据（chapter 是真相源时）
- [orchestrator.py](file:///d:/novel-writer-pure-v3.4/app/agents/orchestrator.py) 的 `run_unit()` 增加入口：如果传 `chapter_id`，自动包装为 Virtual Unit

**验收**：
- 老项目打开 → 自动包装所有 Chapter 为 Virtual Unit
- `orch.run_unit(chapter_id=X)` 自动识别并包装
- 包装后 Virtual Unit 的内容可同步回 Chapter

---

### 工作 2：Event 表 + State Diff（3 天）

**目的**：建立真正的状态流，每个 Unit 结束自动写入状态变化。

**改动**：
- 新增 [040_story_events.sql](file:///d:/novel-writer-pure-v3.4/app/db/migrations/040_story_events.sql)
  ```sql
  CREATE TABLE story_events (
      id TEXT PRIMARY KEY,
      project_id TEXT NOT NULL,
      unit_id TEXT NOT NULL,
      step_no INTEGER DEFAULT 0,
      event_type TEXT NOT NULL,  -- character_state / world_state / item / relationship
      entity_type TEXT NOT NULL,
      entity_name TEXT NOT NULL,
      field_name TEXT NOT NULL,
      old_value TEXT DEFAULT '',
      new_value TEXT DEFAULT '',
      description TEXT DEFAULT '',
      created_at TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))
  );
  CREATE INDEX idx_events_project ON story_events(project_id);
  CREATE INDEX idx_events_unit ON story_events(unit_id, step_no);
  ```
- 新增 [unit_event_service.py](file:///d:/novel-writer-pure-v3.4/app/services/unit_event_service.py)
  - `compute_state_diff(unit_id, entry_state, exit_state) -> list[dict]`
  - `record_events(unit_id, step_no, events)`
  - `list_events_as_of_unit(project_id, unit_id, as_of_step)`
- 修改 [unit_writing_service.py](file:///d:/novel-writer-pure-v3.4/app/services/unit_writing_service.py)
  - `run_unit()` 完成后自动调 `compute_state_diff()` + `record_events()`
  - `rollback_to_snapshot()` 增加 Event 回滚（删除 step_no 之后的事件）

**验收**：
- Unit 完成 → `story_events` 表自动有 Diff 记录
- 回滚到 Step 2 → Event 只剩 Step 2 之前
- `list_events_as_of_unit()` 按段级时间锚点返回

### 工作 3：Chapter Exporter 解耦（2 天）

**目的**：Chapter 降级为 Render，Orchestrator 只产 Unit 流。

**改动**：

  - `ChapterExporter.export_from_unit(unit_id, book_id, strategy, target_chars)`
  - `ChapterExporter.export_for_platform(chapters, platform)` — 番茄 2500 / 起点 4000 / WebNovel 1800
- 保留 [unit_chapter_mapper.py](file:///d:/novel-writer-pure-v3.4/app/services/unit_chapter_mapper.py) 但加废弃标记，新逻辑走 Exporter
- [orchestrator.py](file:///d:/novel-writer-pure-v3.4/app/agents/orchestrator.py) 的 `_dispatch_persist()`：

**验收**：
- Unit 写完 → 不自动创建 Chapter
- UI 点"导出章节" → 调 Exporter → 创建 Chapter

## 风险与回退

**风险**：
1. Event Diff 算法对嵌套 JSON 处理可能漏掉深层字段
2. Virtual Unit 包装可能影响老项目的 UI 表现
3. Orchestrator 全切 Unit 路径可能暴露其他章节模式的隐藏 bug

**回退**：
- 每完成一个工作立即 git commit
- 跑通一个完整流程后再进入下一个工作
- 任何工作失败可 `git revert` 到上一稳定点
- `run_chapter()` 保留代码作为兜底
