# 单元驱动编排重构计划 v5（最终版）

## 概述

**目标**：用 1 个月时间让 Story Engine 真正跑起来，并把 "Guidance（引导）哲学 + Guide 接口契约" 作为整个项目的根脉落地。

**核心哲学**（来自 GPT 第三份分析 + workbuddy 确认）：
> **系统不替作者做决定，也不替 AI 做决定；系统负责提供完整、可解释的故事状态和创作建议，让 AI 和作者在充分理解故事目标的前提下完成创作。**

**三角色职责分离**（直接写入 README 的设计原则）：
- **作者**：负责创意和最终决策。
- **AI**：负责生成文本和提出实现方案。
- **Story Engine**：负责维护故事状态、因果关系和创作建议。

  ## 设计原则（项目宪法）

  ### 三角色职责分离
  - 作者：负责创意和最终决策。
  - AI：负责生成文本和提出实现方案。
  - Story Engine：负责维护故事状态、因果关系和创作建议。

  ```python
  from dataclasses import dataclass, field

  @dataclass
  class Guide:
      """统一的引导接口，所有模块都输出这个"""
      source: str              # "pressure" / "memory" / "voice" / "consistency"
      severity: float          # 0-1，越接近 1 越紧急（但不是判决）
      advice: str              # 人话建议（核心）
      context: dict = field(default_factory=dict)
      evidence_ids: list = field(default_factory=list)

      def to_prompt_block(self) -> str:
          return f"[{self.source} 建议] {self.advice}"
  ```

**验收**：
- 文档存在
- `Guide` dataclass 可被 import，5 个字段全在
- 后续工作直接复用 dataclass，不会再改形状

## 风险与回退（v5 强化）

**风险**：
1. Event Diff 算法对嵌套 JSON 处理可能漏掉深层字段
2. Virtual Unit 包装可能影响老项目的 UI 表现
3. Orchestrator 全切 Unit 路径可能暴露其他章节模式的隐藏 bug
4. Guide 接口可能让某些模块的"判决"语义被弱化（如 consistency 严重冲突）
5. **Event type enum 表扩展性差**（v5 微调 2 的反向风险，加新类型要改 enum 表）
6. **preview() 算法可能误判 truncation 位置**（v5 微调 3 的反向风险）
7. **A/B 灰度新增一倍测试工作量**（v5 微调 4 的反向风险）

**回退**：
- 每完成一个工作立即 git commit
- 跑通一个完整流程后再进入下一个工作
- 任何工作失败可 `git revert` 到上一稳定点
- `run_chapter()` 保留代码作为兜底
- Guide 接口初期与现有接口并存，失败可回退到现有调用
- `use_guide_system=False` 始终可走，与现有 v4 行为一致
- **Event type enum 表**如发现新类型，UPDATE enum 表即可（不像代码硬编码需要改代码）
- **preview() 误判**不影响 export()，预览只是辅助
