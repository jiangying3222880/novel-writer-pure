# 单元驱动编排重构计划

## 概述

**目标**：将章节驱动的 8-Agent 编排系统重构为单元驱动唯一模式。

**顶层决策**：单元驱动作为唯一创作模式，章节只是发布视图。原有 `Orchestrator.run_chapter()` 废弃，所有 Agent 统一适配单元接口。

---

## 当前架构分析

### 章节驱动编排（需废弃）

```
Orchestrator.run_chapter(project_id, chapter_id)
  ↓ 7 步流程
  Step 1: MemoryKeeper → memory_manager.assemble_for_writing(project_id, chapter_id)
  Step 2: ContextBuilder → 按 chapter_id 查世界观/角色/伏笔/风格
  Step 3: Researcher → RAG 检索（不依赖 chapter）
  Step 4: PressureWatcher → narrative_pressures(chapter_id)
  Step 5: Retriever → 文风+桥段 RAG（不依赖 chapter）
  Step 6: Orchestrator._refine() → 精炼 prompt（拼接上面结果）
  Step 7: StoryTeller → AI 写作，返回 content
  Step 8: Editor+Critic → 评估改稿循环
  Step 9: Orchestrator._dispatch_persist() → chapter_service.create_draft() + world_sync
```

**核心问题**：
- 所有 Agent 只认 `chapter_id`，不知道 `unit_id` 存在
- 记忆拼装用 `memory_manager.assemble_for_writing(chapter_id)`（无段级时间锚点）
- 压力计读 `narrative_pressures` 表（按 chapter_id 组织）
- 钩子读 `setting_service.get_setting(project_id, "hooks")`（扁平文本，无段落锚点）
- 关系图谱 `character_tracker` 按 chapter_id 组织

### 单元驱动基础设施（已实现）

| 模块 | 状态 | 调用方 |
|------|------|--------|
| `unit_writing_service.run_unit()` | 完整实现，分段生成+断点快照 | **零调用** |
| `unit_hook_service` | 完整实现，段落锚点钩子 | **零调用** |
| `unit_paragraph_service` | 完整实现，段落 UUID | 部分调用（拆章器） |
| `memory.py` 的 `*_as_of_unit()` 接口 | 完整实现，段级时间锚点 | **零调用** |
| `story_unit_service_v2` | 完整实现，双时间线+状态机 | UI 调用（CRUD） |

## 重构方案

### 1. Orchestrator 重构

**废弃章节入口，新增单元入口**：

```python
class Orchestrator:
    # 废弃
    def run_chapter(...) -> OrchestratorResult:  # 标记 @deprecated
    
    # 新增
    def run_unit(
        self,
        project_id: str,
        unit_id: str,
        *,
        on_step: Optional[Any] = None,
        retention: Optional[float] = None,
    ) -> OrchestratorResult:
        """
        跑完单元写作流程：
          1. 记忆拼装（段级时间锚点）
          2. 上下文构建（unit 版）
          3. 资料研究（不变）
          4. 压力决策（unit 版）
          5. 知识检索（不变）
          6. 精炼提示
          7. 分段写作（调用 unit_writing_service.run_unit()）
          8. 评估改稿（可选）
          9. 落库 + 同步章节
        """
```

**关键变化**：
- Step 1：改用 `memory.list_by_level_as_of_unit(project_id, level, as_of_unit=unit_id)`
- Step 2：改用 `unit_writing_service.build_unit_context(unit_id)`
- Step 4：改用 `unit_pressure_service.get_pressure(unit_id)`（需新增）
- Step 7：改用 `unit_writing_service.run_unit(unit_id, writer_fn=...)`，由 Orchestrator 包装 StoryTeller 为 writer_fn
- Step 9：改用 `unit_writing_service.create_snapshot()` + `unit_chapter_mapper.sync_unit_to_chapters()`

### 2. Agent 重构

**统一适配单元模式**：

| Agent | 当前接口 | 重构后接口 | 改动点 |
|-------|---------|-----------|--------|
| **MemoryKeeper** | `memory_manager.assemble_for_writing(chapter_id)` | `memory.get_l1_l2_as_of_unit(unit_id)` + `memory.list_by_level_as_of_unit()` | 新增 `unit_id` 参数，改调 unit 版接口 |
| **PressureWatcher** | `pressure.get_latest(project_id)` + `narrative_pressures(chapter_id)` | `unit_pressure_service.get_pressure(unit_id)` | 需新增 unit_pressure_service（见下文） |
| **StoryTeller** | `ai.chat(messages)` 单次写作 | 包装为 `writer_fn(refined_prompt) -> str`，由 `run_unit()` 多次调用 | 不直接调 AI，改为回调函数 |
| **Editor/Critic** | `chapter_id` | `unit_id` + 当前生成的段落文本 | 参数改为 unit_id |
| **ContextBuilder** | `chapter_id` 查世界观/角色/伏笔 | `unit_id` 查 entry_characters/entry_world/exit_commitments | 改调 story_unit_service_v2.get() |
| **Researcher/Retriever** | 不依赖 chapter | 不变 | 无需改动 |

**适配层设计**：

```python
class AgentBase:
    # 新增
    def _get_unit_id(self, task: dict) -> Optional[str]:
        """统一获取 unit_id（新模式）"""
        return task.get("context", {}).get("unit_id")
    
    def _get_chapter_id(self, task: dict) -> Optional[str]:
        """获取 chapter_id（废弃，供兼容）"""
        return task.get("context", {}).get("chapter_id")
```

### 3. 钩子跟踪重构

**当前**：`setting_service.get_setting(project_id, "hooks")` → 扁平文本，无结构

**重构后**：`unit_hook_service` → 段落锚点钩子，三事件类型

| 对比项 | 章节 Flat Hooks | 单元 Paragraph Hooks |
|--------|----------------|---------------------|
| 锚点方式 | 无（纯文本） | 段落 UUID + step_no |
| 事件类型 | 无区分 | plant / payoff / reminder / active |
| 生命周期 | 无 | planned → planted → active → fulfilled |
| 时间锚点 | 无 | 单元内按 step_no 过滤 |
| 手动锁定 | 无 | manual_locked 防覆盖 |
| 拆章迁移 | 丢失 | 段落 ID 锚点自动迁移到章节 |

**PressureWatcher 改调**：

```python
# 当前（废弃）
hooks_data = setting_service.get_setting(project_id, "hooks")

# 重构后
from app.services import unit_hook_service
unfulfilled = unit_hook_service.find_unfulfilled_hooks(project_id, up_to_unit_id=unit_id)
active_count = len(unfulfilled)
```

### 4. 压力计重构

**当前**：`narrative_pressures` 表按 `chapter_id` 组织

**问题**：
- 单元模式下无 chapter_id（写作阶段）
- 需按 unit 组织压力记录

**新增服务**：

```python
# app/services/unit_pressure_service.py（新增）

def get_pressure(unit_id: str) -> dict:
    """计算单元叙事压力"""
    unit = story_unit_service_v2.get(unit_id)
    # 1. 查未兑现钩子
    hooks = unit_hook_service.find_unfulfilled_hooks(unit.project_id, up_to_unit_id=unit_id)
    # 2. 查未履行承诺（记忆）
    promises = memory.get_open_promises_as_of_unit(unit.project_id, as_of_unit=unit_id)
    # 3. 查活跃支线（从 unit_memories 提取）
    subplots = _extract_active_subplots(unit)
    
    active_hooks = len(hooks)
    open_promises = len(promises)
    unresolved = len(subplots)
    
    pressure_val = pressure.compute_pressure(active_hooks, open_promises, unresolved)
    zone = pressure.compute_zone(pressure_val)
    
    return {
        "pressure": pressure_val,
        "zone": zone,
        "can_open_hook": zone not in ("orange", "red"),
        "active_hooks": active_hooks,
        "open_promises": open_promises,
        "unresolved_subplots": unresolved,
    }
```

**数据迁移**：
- 保留 `narrative_pressures` 表（兼容已有数据）
- 新增 `unit_pressures` 表（单元压力快照，可选）

### 5. 记忆系统重构

**当前**：`memory_manager.assemble_for_writing(chapter_id)` → L1-L4 拼装

**重构后**：`memory.get_l1_l2_as_of_unit(unit_id)` + `memory.list_by_category_as_of_unit()`

**关键改进**：
- 段级时间锚点：`as_of_step` 参数防止回滚污染
- 单元时间线：按 `story_order` 而非 `chapter_no` 组织
- 全局记忆（无 unit_id）自动包含

**MemoryKeeper 改调**：

```python
def _do_execute(self, task: dict) -> Report:
    unit_id = self._get_unit_id(task)
    if not unit_id:
        return self._build_fail(task, "单元模式下必须传 unit_id")
    
    from app.services import memory
    # L1+L2 核心记忆
    l1_l2 = memory.get_l1_l2_as_of_unit(project_id, as_of_unit=unit_id)
    # L3 场景记忆（可选）
    l3 = memory.list_by_level_as_of_unit(project_id, "L3", as_of_unit=unit_id)
    
    text = "\n".join([m.content for m in l1_l2 + l3])
    return self._build_report(task, {"text": text, ...})
```

## 验证步骤

1. **单元写作流程测试**
   - 创建单元 → 调 `orch.run_unit(unit_id)` → 验证分段生成 → 验证快照保存 → 验证同步章节

2. **段级时间锚点测试**
   - 写到 Step 3 → 回滚到 Step 2 → 验证记忆查询只返回 Step 2 之前的内容

3. **钩子迁移测试**
   - 单元中 plant 钩子 → 拆章 → 验证钩子迁移到章节段落 → 验证 payoff 时锚点准确

4. **压力计测试**
   - 单元未写时压力=0 → plant 3 钩子后压力上升 → payoff 1 钩子后压力下降

5. **关系图谱测试**
   - 单元段落中记录角色状态变化 → 拆章 → 验证章节 character_tracker 正确关联

## 风险与假设

**风险**：
1. **StoryTeller 回调设计复杂度高**：单元分段写作需多次调用，每次要传递不同上下文（开头/中段/结尾策略）
2. **已有项目迁移工作量**：纯章节项目需人工校验钩子迁移（扁平文本 → 段落锚点）
3. **评估改稿循环适配**：单元模式下可能只对完整单元评估，而非每段单独评估

**假设**：
1. 用户已选择单元驱动为唯一模式（不保留章节驱动）
2. 已有 `unit_writing_service` / `unit_hook_service` / `memory.*_as_of_unit()` 实现可用
3. `run_unit()` 的分段策略由 `unit_writing_service` 控制，Orchestrator 只包装 writer_fn
