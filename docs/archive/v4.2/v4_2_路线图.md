```

│   │
│   ├── Event
│   ├── Guide
│   ├── Decision
```

## 二、统一检索方案（优先执行）

### 2.1 背景

v4.0 知识检索有三套分裂逻辑并存：

| 路径 | 位置 | 方式 |
|------|------|------|
| 主检索 | `app/knowledge/finder.py` → `HybridFinder` | BM25 + 向量混合后再融合 |
| 降级 | `app/services/knowledge_service.py` line 131 | HybridFinder 失败时自建纯 BM25Index |
| 独立搜索 | `knowledge_service.search()` | 自有一套搜索方法，不走 finder |

### 2.2 设计原则

| 原则 | 说明 |
|------|------|
| Index = Cache，不是 Source of Truth | 真正数据仍在 SQLite，删掉 Index 可重新 Build 恢复 |
| IndexService 永远只响应事件 | Write Service → EventBus → IndexService → Finder |
| Finder 是唯一入口，Finder 外无检索 | `finder.find()` / `finder.related()` / `finder.context()` |

### 2.3 三接口定义

```python
class Finder:
    def find(self, query: str, **filters) -> list[Hit]:
        """通用搜索。给 UI 搜索框、Ctrl+K 用。"""

    def related(self, entity_id: str, relation_types: list[str] | None = None) -> RelatedResult:
        """关联查询。给图谱、详情面板用。"""

    def context(self, task: ContextTask) -> str:
        """Context Assembly。给 LLM 生成用。内部做预算管理和裁剪。"""
```

### 2.4 执行路线（四步，独立交付）

| Step | 内容 | 风险 | 改动范围 |
|------|------|:----:|---------|
| **Step 1** | Finder 收口：bm25/vector_db 加下划线变内部模块，所有检索走 finder | ⭐ 低 | 全局 import 替换和验证，预估 30 分钟 |
| **Step 2** | IndexService：EventBus 订阅，增量更新索引 | ⭐⭐ 中 | 新增 ~150 行 |
| **Step 3** | Entity Index：Character/Unit/Hook/Decision/Guide/Memory 统一索引 | ⭐⭐ 中 | ~200 行 |
| **Step 4** | Relation Index：关系查询（appears_in/references/generated_by） | ⭐⭐⭐ 中高 | 延迟 |

**Step 1 详细改动**：
- `bm25.py` → `_bm25.py`（内部模块）
- `vector_db.py` → `_vector_db.py`（内部模块）
- `finder.py` 保持不变，对外暴露 `search / extract_for_agent / rebuild`
- `knowledge_service.py` line 131 降级路径改为走 finder fallback

## 五、架构分离原则

### 5.1 Runtime（运行时）

```
app/services/
├── story_compiler.py         # 编译
├── guide_graph.py            # 引导图
├── decision_service.py       # 决策
├── memory_service.py         # 记忆
├── hook_service.py           # 伏笔
├── index_service.py          # 事件驱动索引更新（新增）
└── event_bus.py              # 事件总线
```

### 5.2 Workflow（工作流）

```
app/services/
├── project_service.py        # 项目 CRUD
├── book_service.py           # 卷 CRUD
├── book_outline_service.py   # 卷纲 CRUD
├── story_unit_service_v2.py  # Unit CRUD
├── unit_pool_service.py      # 单元池 CRUD
├── unit_pool_composer.py     # 单元组合
└── publish_service.py        # 发布
```

### 5.3 Knowledge（知识）

```
app/knowledge/
├── capability/               # 能力库
├── domain/                   # 领域库
├── unit_pool/                # 单元池
├── finder.py                 # 唯一检索入口
├── capability.py             # Capability定义
├── _bm25.py                  # 内部模块
├── _vector_db.py             # 内部模块
└── index/                    # 索引
```

### 5.4 Agent（调用层）

```
app/agents/
├── orchestrator.py           # 编排器
├── helpers/
│   ├── storyteller.py        # 写手
│   ├── critic.py             # 评论家
│   └── editor.py             # 编辑
└── prompt_assembler.py       # Prompt 组装
```

### 5.5 分离规则

| 规则 | 说明 |
|------|------|
| Guide 永远轻量 | Guide不直接保存技巧，而是引用Capability Knowledge |
| 知识沉淀在上方 | Agent只是调用者，真正沉淀的是Runtime + Knowledge |
| Agent 可替换 | Agent是Capability的组合，可随时增减而不影响知识 |
| 知识可复用 | 同一份Capability可被多个Agent使用 |
| Finder 唯一入口 | 所有检索走 finder，bm25/vector/knowledge.search 全部消失 |
| Index = Cache | 索引是缓存不是事实源，可重建 |

## 九、风险与处理

| 风险 | 处理方式 |
|------|----------|
| Capability 迁移 | 渐进式，先增加 capability 字段，保持 agent 字段兼容 |
| 知识包兼容性 | 知识包使用独立目录，不影响现有 builtin/local |
| Recipe 复杂度 | 先实现基础模板，逐步增加配置项 |
| 单元池性能 | 增加索引，限制单次检索数量 |
| 卷删除级联 | 提供选项：删除卷及单元 / 仅删除卷 |
| GBrain 冲突 | 明确不集成，避免两个 Runtime 互相套娃 |
