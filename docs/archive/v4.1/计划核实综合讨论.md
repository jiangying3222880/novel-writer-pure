## 三、关键矛盾与风险讨论

### 矛盾 1：两套平行计划，没有任何对齐与依赖声明
收口方案（07-07）的核心目标是"接生"——把已有的 story/ 接通到产品路径，**明确写了 NOT DO LIST**（不新增抽象层、不做 Graph 可视化）。
分卷编排（07-08）却在收口方案之前排了 `030/031/032` 迁移号、新增 `BookOutline`/`VolumeTransition` 独立数据模型；GBrain 版更引入全新检索后端 + 知识图谱。
**这恰恰是收口方案要克制的方向。** 两份新计划没有说明"为什么在收口没完成时就开新坑"，也没有引用收口方案的 Phase 0/2/3 作为前置。

### 矛盾 2：分卷编排计划存在迁移编号冲突
计划写 `030_book_outlines.sql` / `031_volume_transitions.sql` / `032_books_extension.sql`，但仓库里 030–032 早已被占用（`project_author` / `world_relations_enhanced` / `dual_layer_fingerprint`）。**照计划执行会冲突或覆盖已有迁移**，必须重新分配编号（应用 045+）。

### 矛盾 3：文档再次落后于代码（老问题复发）
`v4_1_分析与核实报告.md`（07-08）明确写"orchestrator → story/runtime/unit_runner **未接通**"、"run_unit → review_causality **未调用**"。
但当前 `orchestrator.py` 的 `run_unit` 已经走 v4 快速路径、调用了 `review_causality`(444) / `update_causal_graph`(528) / `UnitRunner`(567)。
**这正是收口方案反复批评的"完成 ≠ 可用、文档 ≠ 现实"——而现在连"核实报告"自己都落后了。** 说明缺少"文档随代码更新"的机制。

### 矛盾 4：收口方案自身严重烂尾
收口方案 4 个 Phase，只有 Phase 1（story/ 链路）被后续改动补上；Phase 0（删 5 个坏 Agent 死代码）、Phase 2（冲突日志 / 增量补丁 / 反向编译，这是 DeepSeek 说的"数控机床"核心差异化）、Phase 3（端到端验证）**全部未做**。等于"接生"只接了一半。

### 矛盾 5：未提交改动持续累积
M1–M5 + orchestrator 改动全部 `git status` 为未提交（上次同步已确认）。新计划若现在动手，会和这批未提交代码混在同一工作区，增加混乱与冲突风险。

### 矛盾 6：GBrain 外部依赖在当前环境不成立
GBrain 要求 `bun install -g gbrain` + `gbrain serve`。当前沙箱无 bun、无 gbrain 服务，且出网被阻断无法安装。**把核心检索替换为强依赖外部服务的方案，在当前阶段是空谈。**

## 四、建议（按优先级）

1. **先收口，再开新坑。** 在分卷编排 / GBrain 动手前，先把收口方案 Phase 0（删死代码）、Phase 2（conflict_log / patch_preview / reverse_compile）、Phase 3（smoke_v4_1_e2e）做完。否则分卷编排又会变成"建好不接"的死骨架——重蹈 v4.0 覆辙。

2. **分卷编排应降级 / 重评。** 
   - 是否真要新建 `BookOutline` / `VolumeTransition` 独立表？还是复用现有 `Book`（已有 `volume_no`）+ `UnitBrief`？避免新增抽象。
   - 迁移编号必须改到 045+，避开已占用的 030–032。
   - 建议作为"接生"完成后的 v4.2 候选，而非与收口并行。

3. **GBrain 降级为"可选后端"，不阻塞主线。** 先保留现有 BM25+向量混合检索（M1 已实现），GBrain 仅在环境具备时作为增强。finder_adapter 的思路（统一接口 + 后端切换）可以保留，但实现优先级排到最后。

4. **建立"文档随代码更新"机制。** 每次代码改动（尤其 orchestrator 链路级）同步更新核实报告 / 收口方案状态。可参考收口方案 §5.13 的 `v4_1_REALITY.md`"现状镜像"思路，由工具在提交时自动生成。

5. **尽快把未提交改动 commit。** 先 `git add` + `commit`（push 留待有网环境），让工作区干净，再启动新计划，避免混合冲突。
