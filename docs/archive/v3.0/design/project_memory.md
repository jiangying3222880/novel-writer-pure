## Hard Constraints
- Tokens提示系统需实现三个位置：首次打开软件的欢迎页（详细介绍各功能花费）、每个花钱功能tab顶部的显眼位置提醒（显示费用）、用户首次开启花钱功能时的弹窗提醒（对比用与不用的效果及费用）
- 仪表盘不添加subtext相关统计
- 段落重写时AI需参考本章潜文本卡并知晓上下文
- 不做跨章检索功能（subtext卡目标是提升章节质量）
- 4.0版本暂不引入plot_deduction插件（用户可通过AI前10章同步生成3个版本的功能自行启用）
- 手动模式下为模板字段添加帮助按钮（每个字段hover显示示例）
- 使用了Subtext的章节在章节编辑tab的列表后面用符号标注
- Subtext三模式：AI自动（默认，含智能跳过过渡章，倾向保守策略）+ 手动（章节级选预置模板微调，6个场景）+ 关闭（默认仅清除后续章节的卡生成，旧章节的卡保留）
- Subtext UI：仅在小说设定tab加"🎭 潜文本卡"子面板（项目级配置+章节级卡管理），项目级只读默认示例
- B2 事件总线: 补3.0 event_bus.py（与B1 IoC容器配套，实现事件广播机制）

## User Communication Style
- 用户为0技术基础，对术语不熟悉，需求/拍板需用业务场景+具体例子描述
- 提问方式：一条条过（不批量），每条先讲清功能+使用/不使用对比举例，再给3选项（补/不做/简化）+推荐，最后记录到项目记忆
- 全量功能对照见 `docs/feature-gap-qa.md`（3.0 vs 4.0 共75条，已拍板16条+待拍板59条）
