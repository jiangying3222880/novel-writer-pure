# BUG修复记录 - 2026-06-02

## 7步工作流端到端数据流修复（12个问题）

通过追踪完整的7步工作流数据注入链路，发现并修复了8个P0级+4个P1级共12个数据注入问题。

---

### P0-1+P0-2: Auditor使用全局word_target，章节级字数目标完全失效

**问题**：`AuditorAgent._fast_fail_check()` 和 `_build_enhanced_prompt()` 使用 `getattr(self.engine, 'word_target', '2500-3000')` 获取全局字数目标，未调用 `self.engine._get_current_chapter_word_target(chapter_no)` 获取章节级设置。当某章设置了不同的 word_target（如5000-6000），Auditor 仍按全局值 2500-3000 做快速失败判定，导致字数合法的章节被误判为失败。

**修复**：
- 新增 `_get_chapter_word_target(chapter_no)` 方法，从 DB 读取 meta + 章节级优先
- `_fast_fail_check()` 签名改为 `_fast_fail_check(chapter_no, content)`，使用章节级字数目标
- `_build_enhanced_prompt()` 同样使用 `_get_chapter_word_target()`

**文件**：`app/workflow/agents/auditor.py`

---

### P0-4: Writer将planner_result整个dict转字符串作为约束清单

**问题**：`WriterAgent.execute()` 中 `constraints=str(constraints)` 将 Planner 返回的完整 dict（含 title, word_target, core_events, characters, prohibitions, hooks_plant, hooks_reap, cool_points, constraints, raw_content 等字段）转为 Python dict 字符串表示形式，如 `{'title': '第1章', 'word_target': '2500-3000', ...}`，可读性极差，AI无法正确理解约束。

**修复**：改为 `constraints.get("raw_content") or constraints.get("constraints")`，优先使用 Planner AI 输出的原始格式化文本。

**文件**：`app/workflow/agents/writer.py`

---

### P0-5+P0-6: core_events和characters未注入Planner prompt，用户大纲完全不可见

**问题**：`get_user_constraints()` 只提取 prohibitions 和 author_requirements，**完全忽略 core_events 和 characters**。用户在章节大纲中精心规划的核心事件和出场角色对工作流完全不可见，Planner 只能凭 AI 自主判断章节内容，与用户大纲脱节。同时 ending（结尾要求）也是死字段。

**修复**：`get_user_constraints()` 增加 core_events、characters、ending 字段的提取，以 `【核心事件】`、`【出场角色】`、`【结尾要求】` 标签格式化输出。

**文件**：`app/db/project_db.py`

---

### P0-7: Auditor完全不知道禁止项列表，D19维度形同虚设

**问题**：`AuditorAgent._build_enhanced_prompt()` 调用 `get_auditor_20d_prompt()` 时没有传递 prohibitions 参数，函数签名中也没有此参数。D19维度（禁止项合规，权重4分）要求审核"全局禁止项+章节禁止项无违反"，但 Auditor 根本不知道禁止项是什么，只能凭空判断。

**修复**：
- `get_auditor_20d_prompt()` 新增 `prohibitions` 参数
- prompt 中新增 `## 禁止项与约束（D19审核依据）` 区块
- `AuditorAgent._build_enhanced_prompt()` 从 DB 读取禁止项并传入
- `get_auditor_prompt()` 包装函数同步添加 prohibitions 参数

**文件**：`app/workflow/agents/auditor.py`、`app/workflow/prompts.py`

### P0-8: 两套auditor prompt不一致

**问题**：`reading_pull_prompts.py` 中存在一个几乎完全重复的 `get_auditor_20d_prompt()`，与 `prompts.py` 版本有三处不一致：
1. 快速失败字数容差：prompts.py 用百分比（±20%），reading_pull_prompts.py 用固定值（±100）
2. 视角阈值：prompts.py 用 `perspective_percent`（配置值），reading_pull_prompts.py 硬编码 `<60%`
3. 快速失败行为：prompts.py 说"直接FAIL跳过检查"，reading_pull_prompts.py 说"标记FAIL但仍需完成全部20维度评分"

**修复**：删除 `reading_pull_prompts.py` 中的重复实现，改为委托给 `prompts.py` 的统一版本。

**文件**：`app/workflow/reading_pull_prompts.py`

---

### Planner视角硬编码

**问题**：`get_planner_prompt()` 中 `get_creative_constitution("第一人称", 90)` 硬编码了视角参数，无论数据库中实际配置的是什么，Planner 生成的约束清单中始终写"第一人称>90%"。同时函数签名缺少 `narrative_perspective` 和 `perspective_percent` 参数（对比 `get_writer_prompt` 是有的）。

**修复**：
- `get_planner_prompt()` 新增 `narrative_perspective` 和 `perspective_percent` 参数
- `get_creative_constitution()` 调用改为使用动态参数
- Planner JSON 输出模板增加 `narrative_perspective` 和 `perspective_percent` 字段
- `PlannerAgent.execute()` 从 DB 读取视角配置并传入

**文件**：`app/workflow/prompts.py`、`app/workflow/agents/planner.py`

### PLANNER输出显示原始JSON

**问题**：`_run_step_agent_results` 中 PLANNER 步骤直接显示 AI 输出的原始 JSON 文本，满是引号、方括号、逗号，完全不可读，且被截断。

**修复**：新增 `_format_planner_display()` 静态方法，将 planner_result dict 格式化为可读的约束清单（带 emoji 标记的标题、核心事件列表、角色列表、伏笔计划、爽点设计、禁止项等）。

**文件**：`app/workflow/engine.py`

---

### P1-1: SHARED_RULES硬编码字数标准

**问题**：SHARED_RULES 质量检测表中硬编码了 "2500-3500字" 和 "2800-3200字"，当用户设置不同的 word_target 时标准错误。且 `_replace_word_target_in_prompt()` 在 Agent 架构下不被调用（各 Agent 直接调用 `ai_engine.chat_async()` 而非 `engine._call_ai()`）。

**修复**：
- SHARED_RULES 中用 `{WORD_TARGET_MIN}`、`{WORD_TARGET_MAX}`、`{WORD_TARGET_GOOD_MIN}`、`{WORD_TARGET_GOOD_MAX}` 占位符替换硬编码值
- `engine._load_data()` 中根据实际 word_target 计算并替换这些占位符

**文件**：`app/workflow/prompts.py`、`app/workflow/engine.py`

---

### P1-2+P1-3: Polisher缺字数和视角约束

**问题**：`get_polisher_prompt()` 不接收 `word_target`、`narrative_perspective`、`perspective_percent` 参数。Polisher 润色时没有字数约束（可能大幅增减字数）和视角约束（可能引入视角违规）。

**修复**：
- `get_polisher_prompt()` 新增 `word_target`、`narrative_perspective`、`perspective_percent` 参数
- prompt 中新增 `## 硬约束` 区块
- `PolisherAgent._build_prompt()` 从 DB 读取配置并传入

**文件**：`app/workflow/prompts.py`、`app/workflow/agents/polisher.py`
