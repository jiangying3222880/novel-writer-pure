## 二、发现的 3 个真实 Bug + 修复

### Bug 1: 导出章节大纲按钮（outline_tab.py:1552）

**严重度**：🟡 P1（用户反馈"导出按钮没用"）

**现象**：
点击"📥 导出章节大纲"按钮，弹出"导出成功"对话框，但生成的文件内容**只有章节标题，没有大纲**。

**根因**：
```python
chapters = db.get_chapters(self.project_id)  # 查的是 chapters 表
for ch in chapters:
    outline = ch.get('outline', '')  # ❌ chapters 表只有 content 字段
```

`chapters` 表 schema 是 `(chapter_no, title, content, word_count)`，**没有 `outline` 字段**。`outline` 字段在 `chapter_briefs` 表中（`core_events` 字段）。

**修复**：
- 同时读 `chapter_briefs`（大纲）和 `chapters`（生成内容）
- 输出包含：core_events（大纲）+ ending（结尾）+ prohibitions（禁止项）+ content（已生成正文）
- 章节标题下分段展示

**用户意图**：导出完整的"章节大纲"——大纲 + 结尾 + 禁止项 + 已生成内容都应包含。

**修复后文件结构**：
```markdown
# 章节大纲

## 第1章：城中村的清晨

[core_events 文本]

**结尾**：[ending 文本]

**禁止项**：[prohibitions 文本]

### 正文（2500 字）

[content 文本]
```

### Bug 2: entity_graph 事件回调空（plugins/entity_graph/__init__.py:57-62）

**严重度**：🔴 P0（用户反馈"插件做了但没显示真正数据"）

**现象**：
1. 项目打开时 → 图谱不刷新
2. 章节生成后 → 图谱不更新关系

**根因**：
```python
def _on_project_opened(**kwargs):
    pass  # ❌ 没有真正刷新图谱


def _on_chapter_generated(**kwargs):
    pass  # ❌ 章节生成后不更新关系
```

事件订阅了，但回调是 `pass`。

**修复**：
- 添加 `_container` 全局变量跟踪当前 container
- 添加 `_get_widget()` 辅助函数
- 两个事件回调都调 `widget.refresh()`

**用户意图**：
- 项目切换时**自动加载对应项目的图谱**
- 章节生成时**自动更新图谱的关系**（新角色出场、新地点、新伏笔）

### Bug 3: usage_analytics step table 缺成功/失败列

**严重度**：🟡 P1（用户反馈"看不到数据"）

**现象**：
"📊 步骤分布"表格只有 5 列（步骤/prompt/completion/total/calls），**没有"成功"和"失败"列**。用户**看不到哪些步骤失败多**。

**根因 1**：`get_usage_by_step` SQL 没有 SELECT `success_calls`/`fail_calls`
**根因 2**：step_table columnCount=5，没加列
**根因 3**：`_refresh_step_table` 没读 success/fail

**修复**：
- DB 层：补全 `get_usage_by_step` 的 success/fail 字段
- UI 层：step_table 改为 7 列（新增"成功""失败"）
- 失败 > 0 的行用**红色**显示（让用户直观看到哪些步骤失败多）

**用户意图**：
- 显示每个步骤的成功率
- 失败次数用红色突出（让用户能快速识别问题步骤）

## 五、建议

1. **数据流验证自动化**：类似 E2E 测试，每个 UI 控件都应该有"操作 → 验证 DB/文件变化" 的测试
2. **插件事件订阅审查**：所有 plugin 应该有 contract——"event X 触发后，plugin Y 必须做 Z"
3. **空回调检测**：可以加 lint 规则，检测 `_on_xxx(**kwargs): pass` 这种空回调
4. **字段名一致性**：outline/content 字段名容易混淆，建议加 schema 注释
