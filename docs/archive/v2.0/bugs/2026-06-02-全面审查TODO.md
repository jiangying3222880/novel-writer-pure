## 🔴 HIGH 优先级（4个）

### Q-1: `is_settler()` 引用不存在的 `self.name`

- **位置**：[app/workflow/agents/base.py:166-167](file:///d:/novel-writer-pure/app/workflow/agents/base.py#L166-L167)

### Q-2: distill_manager.py ThreadPoolExecutor 未复用

- **位置**：[app/memory/distill_manager.py:220-226](file:///d:/novel-writer-pure/app/memory/distill_manager.py#L220-L226)
- **问题**：每次 `force_distill_now` 都 `pool = concurrent.futures.ThreadPoolExecutor(max_workers=1)`，**没有 `pool.shutdown(wait=True)`** 也未复用单例。资源浪费+可能延长进程退出。
- **建议修复**：
  ```python
  # 模块级单例
  _executor = concurrent.futures.ThreadPoolExecutor(
      max_workers=1, thread_name_prefix="distill"
  )
  ```

### Q-3: generator_tab.py 跨线程 lambda 捕获 self 的 GC 风险

- **位置**：[ui/tabs/generator/generator_tab.py:309-313](file:///d:/novel-writer-pure/ui/tabs/generator/generator_tab.py#L309-L313)
- **问题**：3 个 lambda 都捕获 `self`（WorkflowThread 实例）。当 QThread 结束时 `self` 仍被 lambda 引用。如果 `self` 已被 Qt 销毁（C++ 对象 deleted），`emit` 会触发 `RuntimeError: wrapped C/C++ object of type WorkflowThread has been deleted`。
- **建议修复**：
  - 方案 A：用 `weakref.proxy(self)` 替代直接捕获
  - 方案 B：捕获 `self.step_done` 信号对象（信号对象生命周期由 PyQt 管理）

## 🔒 安全问题（3 个）

### S-1: 硬编码默认 license key（MEDIUM）

- **位置**：[app/core/license.py:81-83](file:///d:/novel-writer-pure/app/core/license.py#L81-L83)
- **代码**：
  ```python
  original_key = os.environ.get(
      "NOVEL_WRITER_LICENSE_KEY", "NovelWriter2025SecretKeyForLicense"
  ).encode()
  ```
- **风险**：整个许可证系统可被本地攻击者完全绕过。攻击者可以：
  1. 反编译二进制提取硬编码默认密钥
  2. 计算本地机器的 machine_key
  3. 使用项目提供的 `generate_trial_license()` 或自己生成 license_key
  4. 完全绕过许可证验证
- **建议修复**：
  - 不应在客户端存储或生成可验证的许可证密钥（DRM 在客户端总是可绕过的）
  - 如果要保留许可机制，应当完全在线化（服务端验证）
  - 移除硬编码的 `"NovelWriter2025SecretKeyForLicense"` 默认值（用空字符串或抛错）

### S-2: `_encrypt()` 命名误导（LOW）

- **位置**：[app/core/license.py:546-567](file:///d:/novel-writer-pure/app/core/license.py#L546-L567)
- **问题**：函数命名为 `_encrypt`，但实际上是 `base64(data|signature)`，**没有加密，只有完整性签名**。任何有文件系统访问权限的用户都能解码 license 文件读取所有字段。
- **建议修复**：重命名为 `_sign` 或 `_sign_and_encode`，或实际使用 Fernet 加密 license 数据。

### S-3: keyring 静默失败（LOW）

- **位置**：[app/config/manager.py:180-193](file:///d:/novel-writer-pure/app/config/manager.py#L180-L193)
- **问题**：当 `keyring` 不可用时，秘密将被静默丢失（不会被持久化），下次加载会得到 `""`，迫使 API 调用失败。
- **建议修复**：至少 `logger.warning(f"keyring不可用，密钥将不持久化")`。
