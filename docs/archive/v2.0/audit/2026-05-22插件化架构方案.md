# 插件化架构方案（热插拔版）

> 生成时间：2026-05-22
> 目的：将5个功能模块转化为热插拔插件形式，运行时可随时加载/卸载，无需重启
> 📖 插件开发指南：[插件开发指南.md](插件开发指南.md) — 面向第三方开发者的完整开发文档

## 一、现有微内核基础设施

项目已具备微内核三层架构：

| 组件 | 文件 | 职责 |
|------|------|------|
| Container | app/core/container.py (70行) | 依赖注入容器，支持实例注册/工厂注册/延迟实例化、unregister |
| EventBus | app/core/event_bus.py (89行) | 线程安全事件总线，支持发布/订阅/一次性/取消 |
| PluginManager | app/core/plugin_manager.py (238行) | 插件发现/注册/加载/启用/禁用/依赖排序 |
| IPlugin | app/core/interfaces.py (140行) | 插件基类契约，声明元信息+register()方法 |

### 架构缺口（热插拔视角）

| 缺口 | 说明 | 热插拔影响 |
|------|------|-----------|
| enable/disable只保存配置 | 不执行实际的加载/卸载操作 | **致命**：当前无法运行时切换 |
| 缺少activate/deactivate钩子 | PluginInfo定义了但从未调用 | **致命**：插件无法感知启用/禁用 |
| 容器不支持服务替换 | unregister后register可以，但无原子操作 | **中等**：需确保卸载-重载的原子性 |
| 无UI动态管理 | Tab/菜单在启动时固定创建 | **致命**：无法运行时增删Tab |
| 无资源追踪 | 不知道插件创建了哪些线程/连接/文件句柄 | **高**：卸载时无法正确清理资源 |
| 无依赖检查 | disable时不检查其他活跃插件是否依赖它 | **高**：可能导致运行时崩溃 |

## 三、5个模块的插件化决策

### 3.1 决策总览

| 模块 | 插件化决策 | 热插拔可行性 | 理由 |
|------|-----------|-------------|------|
| 7步工作流模型配置 | **不插件化** | N/A | 本质是配置问题，修复优先级bug即可 |
| 知识库 | **插件化** | ✅ 完全支持 | 索引可独立构建/销毁，检索可动态切换 |
| ~~CLI命令~~ | **整体移除** | N/A | 项目不需要CLI，整体删除 |
| 实体关系图谱 | **插件化** | ✅ 完全支持 | 纯展示功能，Tab可动态增删 |
| Agent提示词 | **插件化** | ✅ 完全支持 | 提示词缓存可失效重建，运行中切换风格 |
| 用量分析 | **插件化** | ✅ 完全支持 | 纯展示+统计功能，记录接口通过事件总线解耦 |

### 3.2 各模块详细分析

#### 模块1：7步工作流模型配置 — 不插件化

**现状缺陷**：

| 缺陷 | 严重度 | 说明 |
|------|--------|------|
| 步骤配置被全局覆盖 | P0 | get_model_for_step()中default_model优先级高于步骤配置，实际运行步骤配置不生效 |
| PLANNER_VERIFY缺少独立配置 | P1 | WORKFLOW_STEPS和PRESET_CONFIGS均缺少此步骤 |
| StepConfig.provider始终为空 | P1 | 预设方案只设置model级别名，无法跨Provider |
| 配置存储碎片化 | P2 | 5个配置文件/位置，无同步机制 |
| StepConfig.enabled未被使用 | P3 | 有字段但无代码检查 |

**修复方案**（不插件化，直接修复）：

1. 修复 `get_model_for_step()` 优先级：步骤配置 > 全局配置
2. 补全 PLANNER_VERIFY 到 WORKFLOW_STEPS 和 PRESET_CONFIGS
3. 预设方案中填充 provider 字段
4. 统一配置存储：合并5个配置文件为1个 `~/.novel-writer-pure/config/app_config.json`
5. 在 WorkflowEngine 中检查 StepConfig.enabled

#### 模块2：知识库 — 热插拔插件

**热插拔关键设计**：
- 每个知识库插件维护独立的索引（文档列表+向量+词汇表）
- 激活时：构建索引 → 注册到容器 → 通知 WorkflowEngine
- 停用时：从容器注销 → 释放索引内存 → 通知 WorkflowEngine
- WorkflowEngine 持有知识库列表（而非单一引用），增删时自动合并/拆分检索结果

**内置库精简方案**：

新知识库已按6类×9题材矩阵重构，目录已创建但文件待导入。插件化后：

| 类别 | 内置基础库（knowledge_builtin） | 扩展语料库（knowledge_corpus） |
|------|-------------------------------|-------------------------------|
| 01_文风语料库 | 每题材1个示例（共9个） | 用户按需导入的语料片段 |
| 02_剧情桥段库 | 每题材1个示例（共9个） | 用户按需导入的剧情桥段 |
| 03_人物人设库 | 每题材1个示例（共9个） | 用户按需导入的人设模板 |
| 04_场景描写库 | 每题材1个示例（共9个） | 用户按需导入的场景描写 |
| 05_写作词语_专属素材总库 | 每子类1个示例（共6个） | 用户按需导入的词语素材 |
| 06_题材全局框架模板库 | 每子类1个示例（共6个） | 用户按需导入的框架模板 |
| **合计** | **~48个文件** | **用户按需导入** |

**设计原则**：
- 内置基础库仅保留每个分类/题材的1个示例文件，作为格式参考和基本功能保障
- 扩展语料库通过 knowledge_local 插件由用户指定本地路径加载
- 用户通过知识库管理界面导入的文件保存到用户库（~/.novel-writer-pure/knowledge/）

#### ~~模块3：CLI命令~~ — 计划整体移除

> ⚠️ CLI模块将从项目中整体移除，不再需要命令行界面。相关代码（app/cli/目录）将在后续统一删除。

#### 模块4：实体关系图谱 — 热插拔插件

**热插拔关键设计**：
- 激活时：创建 QWidget → 动态插入主窗口 Tab → 加载数据
- 停用时：移除 Tab → 销毁 QWidget → 释放内存
- 不参与写作流程，停用后零影响

#### 模块5：Agent提示词 — 热插拔插件

**热插拔关键设计**：
- 激活时：注册提示词目录 → 通知 WorkflowEngine 清除提示词缓存
- 停用时：注销提示词目录 → 回退到默认提示词 → 清除缓存
- WorkflowEngine._read_rule() 每次调用时检查缓存有效性
- 正在执行的工作流不受影响（使用已加载的提示词），下一个工作流使用新提示词

#### 模块6：用量分析 — 热插拔插件

**插件化理由**：
- 用量分析是纯展示+统计功能，不参与写作流程
- 当前 UsageAnalysisDialog 内嵌在 main_window_ui.py 中，耦合度高
- 插件化后可以独立扩展：成本估算、趋势图表、章节级统计、跨项目汇总
- 记录接口（record_usage）通过 EventBus 解耦，停用插件后记录自动降级为静默丢弃

**热插拔关键设计**：
- 核心层保留 `db.record_usage()` 函数（轻量级，仅INSERT一行），确保停用插件后用量数据仍可入库
- 激活时：创建用量分析Tab → 动态插入主窗口 → 订阅 `workflow.step_completed` 事件实时更新
- 停用时：移除Tab → 取消事件订阅 → 数据继续入库（静默）
- 用量分析Tab包含：Token统计、API调用统计、成本估算、步骤用量分布图、日期趋势图、章节级用量

**与现有模块的关系**：

### 4.1 插件生命周期状态机

```
  ┌──────────┐  discover   ┌──────────┐  load       ┌──────────┐
  │ UNFOUND  │────────────→│ DISCOVERED│────────────→│  LOADED  │
  └──────────┘             └──────────┘             └──────────┘
                                                        │     ↑
                                           activate     │     │ deactivate
                                                        ↓     │
                                                    ┌──────────┐
                                                    │ ACTIVE   │
                                                    └──────────┘
                                                         │
                                                    unload ↓
                                                    ┌──────────┐
                                                    │ UNLOADED │
                                                    └──────────┘
```

| 状态 | 说明 | 容器注册 | UI可见 | 事件 |
|------|------|---------|--------|------|
| UNFOUND | 未被发现 | 否 | 否 | - |
| DISCOVERED | 已发现元信息 | 否 | 列表中可见（灰色） | plugin.discovered |
| LOADED | 已加载模块代码 | 否 | 列表中可见（可启用） | plugin.loaded |
| ACTIVE | 已激活运行中 | 是 | 功能完全可用 | plugin.activated |
| UNLOADED | 已卸载释放资源 | 否 | 列表中不可见 | plugin.unloaded |

class IPlugin(ABC):

### 4.3 增强版 PluginManager

```python
class PluginManager:
    def activate_plugin(self, plugin_name: str) -> bool:
        """运行时激活插件（热插拔核心方法）"""
        info = self._plugins.get(plugin_name)
        if not info or info.instance is None:
            return False

        # 1. 检查依赖是否全部已激活
        for dep in info.dependencies:
            dep_info = self._plugins.get(dep)
            if not dep_info or dep_info.state != PluginState.ACTIVE:
                logger.error("[PluginManager] dependency not active: %s", dep)
                return False

        # 2. 调用插件的 activate()
        try:
            activate_fn = getattr(info.instance, "activate", None)
            if activate_fn:
                activate_fn(self.container)
            else:
                # 兼容旧式插件：调用模块级的 activate()
                mod_activate = getattr(info.instance, "activate", None)
                if mod_activate:
                    mod_activate(self.container)

            info.state = PluginState.ACTIVE
            info.enabled = True
            self._save_plugin_config(plugin_name, enabled=True)

            # 3. 发射事件
            event_bus = self.container.get("event_bus")
            if event_bus:
                event_bus.emit("plugin.activated", plugin_name=plugin_name)

            logger.info("[PluginManager] activated: %s", plugin_name)
            return True
        except Exception as e:
            logger.error("[PluginManager] activate failed %s: %s", plugin_name, e)
            return False

    def deactivate_plugin(self, plugin_name: str) -> bool:
        """运行时停用插件（热插拔核心方法）"""
        info = self._plugins.get(plugin_name)
        if not info or info.state != PluginState.ACTIVE:
            return False

        # 1. 检查是否有其他活跃插件依赖它
        for other_name, other_info in self._plugins.items():
            if other_info.state == PluginState.ACTIVE and plugin_name in other_info.dependencies:
                logger.error("[PluginManager] cannot deactivate %s: %s depends on it",
                             plugin_name, other_name)
                return False

        # 2. 调用插件的 deactivate()
        try:
            deactivate_fn = getattr(info.instance, "deactivate", None)
            if deactivate_fn:
                deactivate_fn(self.container)

            info.state = PluginState.LOADED
            info.enabled = False
            self._save_plugin_config(plugin_name, enabled=False)

            # 3. 发射事件
            event_bus = self.container.get("event_bus")
            if event_bus:
                event_bus.emit("plugin.deactivated", plugin_name=plugin_name)

            logger.info("[PluginManager] deactivated: %s", plugin_name)
            return True
        except Exception as e:
            logger.error("[PluginManager] deactivate failed %s: %s", plugin_name, e)
            return False
```

class MainWindowUI(QMainWindow):
    def add_plugin_tab(self, plugin_name: str, widget: QWidget, label: str) -> None:
        """动态添加插件Tab"""
        tab_index = self.tab_widget.addTab(widget, label)
        widget.setProperty("plugin_name", plugin_name)
        widget.setProperty("tab_index", tab_index)
        self._plugin_tabs[plugin_name] = (widget, tab_index)

    def remove_plugin_tab(self, plugin_name: str) -> None:
        """动态移除插件Tab"""
        if plugin_name in self._plugin_tabs:
            widget, tab_index = self._plugin_tabs.pop(plugin_name)
            self.tab_widget.removeTab(tab_index)
            widget.deleteLater()

    def add_plugin_menu(self, plugin_name: str, menu: QMenu) -> None:
        """动态添加插件菜单"""
        action = self.menuBar().addMenu(menu)
        self._plugin_menus[plugin_name] = action

    def remove_plugin_menu(self, plugin_name: str) -> None:
        """动态移除插件菜单"""
        if plugin_name in self._plugin_menus:
            action = self._plugin_menus.pop(plugin_name)
            self.menuBar().removeAction(action)

### 4.5 各类型插件的热插拔流程

#### 知识库插件热插拔

```
激活流程:
  1. activate(container)
     ├── 创建 KnowledgeFinder 实例（lazy=True）
     ├── 后台线程构建索引
     ├── container.register("knowledge.{name}", finder)
     └── event_bus.emit("knowledge.added", source=name)
  2. WorkflowEngine 收到 "knowledge.added" 事件
     ├── 将新知识库加入检索列表
     └── 下次检索时自动合并结果

停用流程:
  1. deactivate(container)
     ├── container.unregister("knowledge.{name}")
     ├── 释放索引内存（finder._docs.clear()）
     └── event_bus.emit("knowledge.removed", source=name)
  2. WorkflowEngine 收到 "knowledge.removed" 事件
     ├── 从检索列表移除该知识库
     └── 正在执行的工作流不受影响（已获取的结果仍有效）
```

#### 实体图谱插件热插拔

```
激活流程:
  1. activate(container)
     ├── 创建 EntityGraph 实例
     ├── 创建 GraphWidget
     ├── main_window.add_plugin_tab("entity_graph", widget, "🔗 实体图谱")
     ├── container.register("entity_graph", graph)
     └── graph.load_data(project_id)

停用流程:
  1. deactivate(container)
     ├── main_window.remove_plugin_tab("entity_graph")
     ├── container.unregister("entity_graph")
     └── graph.clear()  # 释放内存
```

#### 提示词插件热插拔

```
激活流程:
  1. activate(container)
     ├── container.register("prompts.{name}", prompt_dir)
     └── event_bus.emit("prompts.changed", source=name)
  2. WorkflowEngine 收到 "prompts.changed" 事件
     ├── 清除 _read_rule() 缓存
     └── 下次工作流执行时使用新提示词

停用流程:
  1. deactivate(container)
     ├── container.unregister("prompts.{name}")
     └── event_bus.emit("prompts.changed", source="default")
  2. WorkflowEngine 收到 "prompts.changed" 事件
     ├── 清除缓存，回退到默认提示词
     └── 正在执行的工作流不受影响
```

#### 用量分析插件热插拔

```
激活流程:
  1. activate(container)
     ├── 创建 AnalyticsWidget（Tab组件）
     ├── main_window.add_plugin_tab("usage_analytics", widget, "📊 用量分析")
     ├── event_bus.on("workflow.step_completed", self._on_step_completed)
     ├── event_bus.on("workflow.step_failed", self._on_step_failed)
     └── widget.refresh()  # 加载历史数据

停用流程:
  1. deactivate(container)
     ├── event_bus.off("workflow.step_completed", self._on_step_completed)
     ├── event_bus.off("workflow.step_failed", self._on_step_failed)
     ├── main_window.remove_plugin_tab("usage_analytics")
     └── 数据继续入库（db.record_usage仍在核心层运行）

关键设计:
  - db.record_usage() 保留在核心层，停用插件仅影响展示，不影响数据入库
  - WorkflowEngine._record_usage() 改为同时发射 EventBus 事件:
    event_bus.emit("usage.recorded", step=step, prompt_tokens=pt, completion_tokens=ct)
  - 插件通过事件实时更新统计，无需轮询数据库
```

### 4.6 资源追踪与安全清理

每个插件在 activate 时必须声明其创建的资源，deactivate 时 PluginManager 验证清理是否完整：

```python
@dataclass
class PluginResources:
    threads: List[QThread] = field(default_factory=list)
    timers: List[QTimer] = field(default_factory=list)
    container_services: List[str] = field(default_factory=list)
    event_subscriptions: List[tuple] = field(default_factory=list)  # (event_name, handler)
    ui_tabs: List[str] = field(default_factory=list)
    ui_menus: List[str] = field(default_factory=list)
    file_handles: List[Any] = field(default_factory=list)
```

PluginManager 在 deactivate 后验证：

```python
def _verify_cleanup(self, plugin_name: str, resources: PluginResources) -> None:
    for thread in resources.threads:
        if thread.isRunning():
            logger.warning("[PluginManager] plugin %s left running thread", plugin_name)
            thread.quit()
            thread.wait(3000)
    for service_name in resources.container_services:
        if self.container.has(service_name):
            logger.warning("[PluginManager] plugin %s left service: %s", plugin_name, service_name)
            self.container.unregister(service_name)
```

### 4.7 热插拔安全规则

| 规则 | 说明 |
|------|------|
| 工作流执行中禁止停用 | 如果 WorkflowEngine 正在运行，禁止停用知识库/提示词插件，提示用户等待 |
| 依赖插件禁止先停用 | 如果插件A依赖插件B，必须先停用A再停用B |
| 停用超时强制清理 | deactivate() 超过5秒未返回，强制清理资源 |
| 激活失败自动回滚 | activate() 抛异常时，自动调用 deactivate() 清理已分配资源 |
| 事件驱动通知 | 所有状态变更通过 EventBus 广播，其他模块按需响应 |

### 6.4 待修复Bug

#### Bug: model_config.py 文件读取编码错误

**报错信息**：
```
[WARNING] ui.dialogs.model_config (model_config.py:197): 加载模型配置失败: 'gbk' codec can't decode byte 0xa7 in position 422: illegal multibyte sequence
```

**根因**：Windows 系统下 `open()` 不指定 `encoding` 时默认使用 GBK 编码，当 JSON 文件包含中文字符（如模型名称"默认模型"、provider"火山方舟"等）时解码失败。

**受影响代码**：

| 文件 | 行号 | 操作 | 缺陷 |
|------|------|------|------|
| model_config.py | 194 | `open(configs_file)` 读取 model_configs.json | 缺少 `encoding="utf-8"` |
| model_config.py | 203 | `open(active_config_file)` 读取 ai_config.json | 缺少 `encoding="utf-8"` |
| model_config.py | 490 | `open(active_config_file, "w")` 写入 ai_config.json | 缺少 `encoding="utf-8"` + `ensure_ascii=False` |

**修复方案**：所有 `open()` 调用统一添加 `encoding="utf-8"`，写入时添加 `ensure_ascii=False`：

```python
# 读取（第194行）
with open(configs_file, encoding="utf-8") as f:
    self.all_configs = json.load(f)

# 读取（第203行）
with open(active_config_file, encoding="utf-8") as f:
    active_config = json.load(f)

# 写入（第490行）
with open(active_config_file, "w", encoding="utf-8") as f:
    json.dump(self.all_configs[model_name], f, indent=2, ensure_ascii=False)
```

**全局排查**：实施时需全局搜索项目中所有 `open(` 调用，确保涉及中文内容的文件操作均指定 `encoding="utf-8"`。

## 九、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 工作流执行中停用知识库 | 检索结果不完整 | WorkflowEngine 运行时锁定依赖插件，禁止停用 |
| 提示词切换导致风格不一致 | 同一章节前后风格不一 | 仅在章节间隙切换，正在执行的步骤使用旧提示词 |
| 用量分析停用后数据丢失 | 新数据无法入库 | 核心层保留 db.record_usage()，数据持续入库，停用仅影响展示 |
| 知识库索引构建耗时 | 激活时UI短暂卡顿 | 索引构建在后台线程执行，激活后异步通知 |
| 插件间循环依赖 | 无法确定加载/停用顺序 | 禁止循环依赖，PluginManager 拓扑排序验证 |
| Python模块缓存 | importlib缓存导致重新加载旧代码 | 使用 importlib.reload() 或子进程隔离 |
| 内存泄漏 | deactivate后资源未释放 | PluginResources 追踪 + 超时强制清理 + 内存监控 |
| UI线程安全 | 非主线程操作UI组件 | 所有UI操作通过信号槽回到主线程 |
