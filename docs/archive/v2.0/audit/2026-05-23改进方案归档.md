### P2：start_from_step 处理不一致 ✅ 已修复

**问题定位**：`app/workflow/engine.py`

> **修复记录**：统一所有 7 个步骤的 `start_from_step` 跳步逻辑。AUDITOR/REVISER 在首轮时若 `start_from_step > step_no` 则从 checkpoint 加载；POLISHER 增加 `start_from_step > 5` 判断；PLANNER_VERIFY 增加 `start_from_step > 6` 判断。审核循环内（review_round > 0）不受 `start_from_step` 约束。

Auditor 对 `start_from_step` 有特殊处理（line 385）：
```python
if start_from_step <= 3 and review_round == 0:
    # 执行 Auditor
```

但其他步骤（Reviser/Polisher）未做同样处理，导致跳步逻辑不一致。

**解决方案**：统一 `start_from_step` 处理逻辑

```python
# 所有步骤统一判断
for step_no, step_name in STEP_ORDER:
    if start_from_step > step_no:
        # 从 checkpoint 加载，不执行
        results[step_name] = db.load_checkpoint(...)
    else:
        # 正常执行
        await self._run_step_agent_results(...)
```

**改动点**：

| 文件 | 改动内容 |
|------|---------|
| `app/workflow/engine.py` | 统一 start_from_step 判断逻辑 |

```python
def tokenize_chinese(text: str) -> List[str]:
    """公共分词工具"""
    try:
        import jieba
        jieba.setLogLevel(jieba.logging.INFO)

    return words
```

```python
class ConfigWizard(QWizard):
    """首次配置向导"""
    def __init__(self):
        super().__init__()
        self.addPage(self._create_welcome_page())
        self.addPage(self._create_api_key_page())
        self.addPage(self._create_model_page())
        self.addPage(self._create_summary_page())
    
    def _create_api_key_page(self):
        """API Key 配置页"""
        page = QWizardPage()
        layout = QVBoxLayout()
        layout.addWidget(QLabel("请输入您的 AI API Key"))
        self.api_key_input = QLineEdit()
        self.api_key_input.setEchoMode(QLineEdit.Password)
        layout.addWidget(self.api_key_input)
        
        # 一键填充推荐配置
        btn = QPushButton("使用推荐配置（火山方舟）")
        btn.clicked.connect(self._fill_recommended)
        layout.addWidget(btn)
        
        page.setLayout(layout)
        return page
```

**问题定位**：`app/core/plugin_manager.py:304-313`

> **修复记录**：Phase 0 实施。PluginManager 重写，新增 `deactivate_plugin()` 方法，正确调用 `_deactivate_fn` 并验证资源清理。`disable()` 方法改为调用 `deactivate_plugin()` 实现即时生效。

```python
def deactivate_plugin(self, plugin_name: str) -> bool:
    ...
    info.enabled = False  # 只设置标志，未调用 deactivate()
```

**影响**：插件创建的资源（线程、连接、文件句柄）未清理。

**解决方案**：

```python
def deactivate_plugin(self, plugin_name: str) -> bool:
    ...
    # 调用 deactivate 函数
    if info._deactivate_fn:
        try:
            info._deactivate_fn(self.container)
        except Exception as e:
            logger.warning(f"[PluginManager] deactivate failed: {e}")
    
    info.state = PluginState.DEACTIVATED
```
