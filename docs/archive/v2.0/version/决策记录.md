### D-008: Ruff Lint 229个问题全量修复策略
- **日期**: 2026-05-23
- **背景**: 项目全面Ruff检查发现229个问题，涵盖10种规则。需要决定修复策略，尤其是F821（未定义名称）和E402（导入不在顶部）的处理方式
- **方案A**: 仅修复严重问题（F821/F601），其余忽略
- **方案B**: 全部修复，对设计合理的模式使用noqa标记
- **方案C**: 全部修复，重构所有代码消除noqa需求
- **利弊分析**:
  - A: 工作量最小，但229个问题会持续产生噪音，掩盖真正的新问题
  - B: 全部通过ruff检查，对合理模式（可选依赖faiss/np、测试文件sys.path操作、TYPE_CHECKING前向引用）使用noqa，代码质量全面提升

  2. vector_db.py中faiss可用性检查导入（`# noqa: F401`）
  3. tests中sys.path操作后的导入（`# noqa: E402`）

### D-009: 记忆配置展示7Agent记忆方案
- **日期**: 2026-05-23
- **背景**: 需要在记忆配置中展示7Agent的记忆，便于调试和理解Agent决策过程
- **方案A**: 展示Agent的"记忆视角"（复用build_context_for_step）
- **方案B**: 启用私有记忆（在各Agent中添加remember_private调用）
- **方案C**: 混合方案（共享记忆 + Agent记忆视角 + Agent私有记忆）
- **利弊分析**:
  - A: 零成本，直观展示"Agent看到什么"，但无私有数据
  - B: 有私有数据，但需修改所有Agent代码，增加耦合
  - C: 最全面，既有共享记忆视角又有私有数据，但实现成本最高
- **最终决策**: 方案C — 混合方案：
  1. 记忆查看器新增"👁️ Agent记忆视角"Tab：展示各Agent从共享记忆中读取的内容
  2. 记忆查看器新增"🔒 Agent私有记忆"Tab：展示各Agent的私有数据
  3. 6个Agent新增私有记忆写入：在execute()成功后调用remember_private() + persist_private()
- **决策人**: 用户确认
