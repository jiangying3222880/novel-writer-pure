## 版本号规则
- MAJOR.MINOR.PATCH
- PATCH: BUG修复、小优化
- MINOR: 新功能、插件新增、UI改进
- MAJOR: 架构重构、不兼容变更

## v3.2 候选方案

> 来自 hermes 的功能建议（2026-06-05），按 ROI 排序。本节只列**待评估方案**，
> 不代表已排期。每一项需经过"工作日估算 + 依赖关系 + 是否破坏 3 阶段范式"
> 三重评估后再决定纳入 v3.2。

### v3.2-A：生成→审阅→修改工作流（POST_PERSIST_REVIEW）⭐⭐⭐

**问题**：当前 3.1 流程在 11 章后是全自动 Persist 落库，作者失去"读→改"介入点。
真人写作必然要"写完读 30 分钟 → 改 5 处"，AI 跑完直接落库对长篇不利。

**方案**：**不破坏 3 阶段范式，加 UI 审阅层**。章节落库后，作者可在章节列表
点击"📝 审阅"按钮，弹窗支持 3 个动作：

| 动作 | 效果 | 实现 |
|------|------|------|
| ✅ 接受 | 无操作 | 默认 |
| ⚠️ 标记问题 | 写入 `chapters.review_flag = 'problem'` | DB 字段扩展 + UI 按钮 |
| 🔄 重新生成 | 触发单章重写，复用 USER_CONFIRM 反馈注入 | 复用 v3.1 USER_CONFIRM |

**触发**：EventBus 发 `chapter.persisted` 事件 → 章节列表 UI 显示"待审阅"标记

**ROI**：⭐⭐⭐ 高。零破坏性，3-5 天工作量，纯 UI + DB 字段。

---

### v3.2-B：卷级规划（Volume-Level Planning）⭐⭐

**问题**：50 章以上长篇没有"卷"概念，所有章节线性排列，缺少情绪曲线/伏笔收束
的中观管理。当前 `chapter_briefs.volume_no` 字段存在但**未约束使用**。

**方案**：
- 新增 `volume_plans` 表（`volume_no`, `title`, `emotion_curve`, `core_conflict`,
  `planned_foreshadowing_reap`, `start_chapter`, `end_chapter`）
- `meta` 表加 `current_volume` 字段
- 章节大纲落库时校验 `chapter_no ∈ [start_chapter, end_chapter]`
- 与叙事压力仪表盘配合：压力值按卷计算，**每卷独立评分**

**依赖**：
- 叙事压力仪表盘（v3.2 之前未实现，需先做）
- 章节大纲逻辑改造（chapter_briefs → volume_plan 二级结构）

**ROI**：⭐⭐ 中。架构级改动，1-2 周工作量，**与 v3.2-A 可并行**（互不依赖）。

---

### v3.2-C：写作风格参考注入（Wiki-Style Reference）⭐⭐⭐

**问题**：项目有 4871 本小说的 wiki 知识库（`knowledge/`），但 3.0/3.1 完全未使用。
作者无法用"我想要 X 小说的风格"作为参考，全靠 AI 学前 10 章。

**方案**：
- 大纲 Tab 新增"风格参考"区域，用户从 wiki 选 1 本作为参考
- 新增 `ReferenceStyleProfile` 数据类（句长分布 / 对话占比 / POV 偏好 / 段落长度）
- 风格特征提取逻辑（NLP 轻量分析，不调 LLM）
- 注入 Writer prompt："请模仿 X 小说的 X 风格特征"
- 优先级：风格参考 > 自动学习 > 全局默认

**依赖**：
- wiki 文档结构标准化（当前各 wiki 格式不一）
- 风格特征提取器（独立模块，可单独测试）

**ROI**：⭐⭐⭐ 高差异化。**最有卖点**，但实现复杂（2-3 周工作量），建议放 v3.2 末段或 v3.3。
