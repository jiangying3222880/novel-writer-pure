## 二、架构设计：Story OS 10层设计

项目采用 **Story OS** 架构，将写作流程抽象为 10 个层次：

```
┌─────────────────────────────────────────────────────────────┐
│ L10: Runtime Loop          → story/engine/story_engine.py   │
│                              story/runtime/unit_runner.py   │
├─────────────────────────────────────────────────────────────┤
│ L9: Publish Layer          → app/exporter/                  │
├─────────────────────────────────────────────────────────────┤
│ L8: Observability UI       → app/ui/observe/                │
├─────────────────────────────────────────────────────────────┤
│ L7: Event System           → story/events/*                 │
│                              app/db/ (SQLite持久化)          │
├─────────────────────────────────────────────────────────────┤
│ L6: Prompt OS              → story/prompt/*                 │
├─────────────────────────────────────────────────────────────┤
│ L5: Decision Layer         → story/decision/*               │
├─────────────────────────────────────────────────────────────┤
│ L4: Agent Simulation       → app/agents/*                   │
├─────────────────────────────────────────────────────────────┤
│ L3: Guide Engine           → story/guide/*                  │
├─────────────────────────────────────────────────────────────┤
│ L2: Story State (SSOT)     → story/state/*                  │
├─────────────────────────────────────────────────────────────┤
│ L1: Core Infrastructure    → app/core/                      │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 核心基础设施 (L1)

| 模块 | 文件 | 职责 |
|------|------|------|
| **IoC容器** | `app/core/container.py` | 依赖注入、单例管理、Protocol查找 |
| **事件总线** | `app/core/event_bus.py` | 内部发布订阅 |
| **配置系统** | `app/core/config.py` | 应用配置管理 |
| **接口定义** | `app/core/interfaces.py` | LLMClient、Retriever、Agent等协议 |

**设计亮点**：`Container` 支持按 `Protocol` 类型查找实例，便于测试时替换 Mock 实现。

### 2.2 故事状态 (L2) - SSOT

`story/state/story_state.py` 定义了不可变的 `StoryState`：

```python
@dataclass(frozen=True)
class StoryState:
    unit_id: str
    characters: dict[str, CharacterSnapshot]
    hooks: list[HookSnapshot]
    world: WorldSnapshot
    commitments: list[CommitmentSnapshot]
    memories: list[str]
```

**设计原则**：
- **不可变**：`frozen=True` 确保状态不可被意外修改
- **事件溯源**：通过 `apply_event()` 返回新实例实现状态变更
- **单一事实源**：`StoryState` 是运行时唯一的状态表示，不直接写DB

### 2.3 引导引擎 (L3)

`story/guide/` 实现了 5 源信号收集：

| 信号源 | 文件 | 职责 |
|--------|------|------|
| Pressure | `pressure_source.py` | 节奏压力信号 |
| Memory | `memory_source.py` | 记忆信号 |
| Consistency | `consistency_source.py` | 一致性信号 |
| Voice | `voice_source.py` | 语气/风格信号 |
| Hook | `hook_source.py` | 伏笔信号 |

`GuideSource` 协议定义了统一接口：

```python
@runtime_checkable
class GuideSource(Protocol):
    source_id: str
    def collect(self, unit_id: str, *, project_id: str = "", state=None) -> list[DecisionSignal]: ...
```

### 2.4 决策层 (L5)

`story/decision/engine.py` 将信号转换为叙事策略：

**4种策略**：
- `RESOLVE` (收束)：信号方向一致，按选定路径推进
- `EXPLODE` (爆发)：高张力信号集中，加速回收伏笔
- `DETOUR` (转向)：存在维度冲突，引入意外转折
- `DELAY` (延后)：信号不足或冲突过多，暂缓推进

**决策流程**：
1. 计算维度向量 (`compute_dimension_vector`)
2. 检测信号冲突 (`_detect_signal_conflicts`)
3. 选择策略 (`_select_strategy`)
4. 生成写作指令 (`_build_instruction`)

### 2.5 Prompt OS (L6)

`story/prompt/compiler.py` 将 SUC (Story Understanding Context) 和策略编译为 LLM 可用的 Prompt：

```python
def compile(suc, strategy_result):
    system_lines = [WRITER_SYSTEM_TEMPLATE]  # 写作原则
    user_lines = [seg.content for seg in suc.ranked_segments()]
    user_lines.append(strategy_result.instruction)  # 决策指令
    user_lines.append(_build_task_block(unit_title, unit_synopsis))  # 写作任务
```

### 2.6 事件系统 (L7)

`story/events/types.py` 定义了不可变的 `StoryEvent`：

```python
@dataclass(frozen=True)
class StoryEvent:
    id: str
    type: str  # character_state, hook_plant, unit_completed 等
    payload: dict[str, Any]
    causality: dict[str, Any]  # 因果关系追踪
    timestamp: float
    unit_id: str
    project_id: str
```

**事件类型**：角色事件、世界事件、伏笔事件、承诺事件、写作事件。

### 2.7 Agent 模拟 (L4)

`app/agents/base.py` 定义了 Agent 基类：

| Agent角色 | 职责 |
|-----------|------|
| **WRITER** | 写手/士兵 |
| **EDITOR** | 编辑(评估6维) |
| **CRITIC** | 批评家(风格一致性) |
| **RETRIEVER** | 检索(文风+桥段RAG) |
| **RESEARCHER** | 研究员(历史/题材资料) |
| **MEMORY** | 记忆(L1-L4拼装) |
| **PRESSURE** | 压力计 |

**设计要点**：
- 单职责：每个 Agent 只负责一种能力
- 状态机：`idle → working → done/error/cancelled`
- 上下文隔离：每次 `execute()` 复制 task.context
- 汇报机制：通过 `Report` 对象唯一通讯

## 三、关键设计模式

### 3.1 不可变状态模式
`StoryState` 和 `StoryEvent` 都使用 `@dataclass(frozen=True)`，确保状态变更只能通过事件溯源实现。

### 3.2 事件溯源模式
状态变更通过 `apply_event()` 返回新实例，配合 `EventStore` 持久化实现完整的事件回放能力。

### 3.3 依赖注入模式
`Container` 提供 IoC 能力，支持工厂模式、单例管理、Protocol 查找。

### 3.4 策略模式
决策层根据信号维度向量选择不同的叙事策略（RESOLVE/EXPLODE/DETOUR/DELAY）。

### 3.5 观察者模式
`ThemeObserver` 和事件总线实现了主题变更和跨模块通信。

### 3.6 协议模式
使用 `typing.Protocol` + `@runtime_checkable` 定义接口，实现松耦合。

## 八、总结

**Novel Writer v4.0** 是一个架构先进的 AI 辅助小说创作工具，核心亮点包括：

1. **Story OS 架构**：将写作流程抽象为 10 个层次，职责清晰，易于扩展
2. **不可变状态模式**：`StoryState` 作为单一事实源，通过事件溯源管理状态
3. **引导-决策引擎**：5源信号收集 + 策略选择，实现智能叙事指导
4. **Agent 隔离机制**：每个 Agent 独立运行，通过 Report 汇报，避免上下文污染
5. **向后兼容性**：完整支持从 v3.4 迁移，数据库增量升级

**当前状态**：核心架构已完成，正处于功能完善阶段，UI 框架已就绪，部分业务逻辑待实现。
