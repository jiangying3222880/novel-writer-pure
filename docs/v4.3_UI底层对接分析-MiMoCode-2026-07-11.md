## 二、核心问题：哪些是"黑箱"

### 黑箱 1：写作过程不可见

用户点"生成"→ 等待 → 看到结果。中间发生了什么？

```text
用户看到的:
  [生成中...] → [完成]

实际发生的:
  collect_guides (10源) → decision → SUC → compile → refine
  → 5-Agent研究 → 写作 → 评估循环 → 持久化
  → UIStateBridge → EventBus → UI刷新
```

**缺失：** 每个步骤的进度、耗时、中间结果不可见。

### 黑箱 2：Guide 冲突不可追溯

GuideGraphPage 显示冲突，但：
- 冲突何时产生？不可知
- 冲突是否被解决？不可追踪
- conflict_log 写入了但 UI 没读

### 黑箱 3：决策过程不可审查

Decision 记录了哪些 Guide 被采纳，但：
- 为什么采纳 A 而不采纳 B？不可见
- 决策的权重矩阵不可视

### 黑箱 4：事件流不可见

event_store 记录了所有事件，但：
- 没有 UI 展示事件时间线
- 事件对状态的影响不可追溯

## 三、可落地方案（按优先级）

### P0：写作管线进度可视化（最高价值）

**现状：** 用户点"生成"后看不到过程
**目标：** 每个步骤实时显示进度 + 耗时

**改动：** GenerateTab 已有 `_on_step` 回调，只需扩展显示：

```
┌─────────────────────────────────┐
│ ✅ Guide 收集 (10源, 0.2s)      │
│ ✅ Decision 策略选择 (0.1s)     │
│ ✅ Agent 研究 (5个, 2.3s)       │
│ ✅ Prompt 精炼 (0.3s)           │
│ ⏳ 写作中... (预计 15s)         │
│   ├─ Writer: 进行中             │
│   ├─ Editor: 等待               │
│   └─ Critic: 等待               │
│ ✅ 评估完成 (score=82)           │
│ ✅ 持久化 (0.1s)                │
│ ✅ UI 刷新 (0.05s)             │
└─────────────────────────────────┘
```

**改动范围：** GenerateTab._on_step() + 新增 StepProgressWidget
**风险：** 低（只读展示）

### P1：Guide 冲突追溯

**现状：** GuideGraphPage 显示冲突但无时间维度
**目标：** 冲突产生时间 + 解决状态 + conflict_log 可查

**改动：**
1. conflict_log 的 `created_at` + `resolved_at` 已有字段
2. GuideGraphPage 加"历史冲突" tab，查询 conflict_log 表
3. 冲突边加时间戳

**改动范围：** GuideGraphPage + conflict_log 查询
**风险：** 低

### P2：事件流时间线

**现状：** event_store 数据不可见
**目标：** 可视化事件时间线，追溯状态变更

**改动：**
1. 新建 EventTimelineWidget（复用 StoryUnitTab 的列表模式）
2. 查询 event_store.list_for_unit()
3. 按时间排序显示事件 + 状态变更 diff

**改动范围：** 新建 Widget + 接入 StoryUnitTab 或独立页面
**风险：** 中（新 UI 组件）

### P3：决策权重可视化

**现状：** DecisionHistoryPage 只显示文本
**目标：** 可视化决策权重矩阵

**改动：**
1. 从 decision_service 查询 Decision 记录
2. 用 QPainter 自绘权重条形图（复用 TrendChart 模式）
3. 显示每个 Guide 的 priority × confidence 权重

**改动范围：** DecisionHistoryPage 扩展
**风险：** 低

## 五、不做的事情

- ❌ 不做 3D 可视化/力导向图（过度设计）
- ❌ 不做实时 WebSocket 推送（QTimer 足够）
- ❌ 不做独立的"可观测性平台"（内嵌到现有页面）
